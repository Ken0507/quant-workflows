# console-mode

> 把当前主会话变成一个有台账、有依赖、有独立验收的任务控制台，让开发和验证由可恢复的执行者完成。

## 供应链位置

```text
用户目标 / 已确认上下文 ──▶ [console-mode] ──▶ 执行回执、验收回执、下一步工单
```

- **上游：** 用户明确的目标、约束、已有授权和原始资料；进入模式前要把这些整理进工单上下文。
- **下游：** `codex-pool` 或用户明确选择的 `use-macmini` 执行者，以及独立验收工单；验收通过后才进入下一项工作。
- **兄弟工序：** `use-macmini` 负责 Macmini 派单细节；`console-mode` 负责会话级角色边界、台账、恢复和推进，不替代它。

## 问题陈述

长任务中，主会话容易在“推进”名义下重新打开仓库、写代码、跑测试，导致控制台和执行者职责混在一起；网络断线或上下文压缩后又可能重复启动 writer，或者把 worker 自报当验收。用户需要一个持久到当前会话的控制面：主会话只管总目标和调度，实质工作有工单、状态和可读回执。

## 解决方案

技能在激活后建立任务台账，为每项工作记录上下文、依赖、单一 writer、允许/禁止操作、执行设置、交付路径和验收标准。默认通过 `codex-pool` 用 `gpt-6-astra / xhigh / service_tier=default` 执行；每次显式覆盖 profile 里的 Fast。它用 CLI JSONL 和 thread ID 做有界等待与原会话恢复，把 `EXECUTION_REPORTED` 与独立 `PASSED` 分开。用户明确指定 Macmini 时交给现有 `use-macmini`，并额外派 84 侧验收。

## 设计决策

| 决策 | 选择 | 原因 | 替代方案 |
|------|------|------|----------|
| 默认执行端 | `codex-pool` + astra xhigh | 符合用户指定的默认执行供应链 | 直接用主会话会破坏控制台边界 |
| tier | 每次显式 `default` | 本地 lgj profile 默认是 `fast`，不能静默继承 | 修改全局 profile 会影响其他会话 |
| 状态 | 工单目录的台账、STATUS、RECEIPT | 压缩/恢复和多步推进需要可读的持久证据 | 只靠聊天历史容易丢 writer 身份 |
| 验收 | 独立 acceptance work order | 退出码和自报不能证明行为正确 | 同一执行者自验会掩盖缺陷 |
| 调度实现 | 复用 Codex CLI，不新建 scheduler | 需求是角色协议，不是常驻服务 | 新建后台队列会增加重试和权限风险 |
| Macmini | 按已安装 `use-macmini`，另派 84 验收 | 保留 Claude-native 配置和既有凭据红线 | 伪造 GPT 参数或让 Macmini 自验都不可靠 |
| 模式边界 | 只在当前会话生效 | 不改变用户全局行为 | 修改 AGENTS/config 会产生跨会话副作用 |

## 已放弃方案

### 全局 AGENTS / provider 配置改造

这会让一个会话的偏好泄漏到其他任务，且无法表达“本轮覆盖还是以后都覆盖”。因此只在当前会话台账中保存设置。

### 自建常驻调度器和自动重试队列

本任务只需要有界派发、thread 恢复和独立验收；常驻服务会制造重复 writer、凭据和停止权限问题。保留可读模板，让控制台按证据做下一步决定。

### 用主会话或同一 worker 完成验收

这会把“我跑过了”误当成“结果被证实”。验收独立成工单，任何失败都回到有证据的返工路径。

## FAQ

**Q: 进入模式后没有任务怎么办？**
A: 只确认模式已激活并等待，不编造工作。

**Q: `codex-pool` 为什么还要写 `service_tier=default`？**
A: 当前本地 lgj profile 可能默认 `fast`；命令行显式覆盖才能实现本模式的默认约定，且不修改全局配置。

**Q: worker 说完成了就可以推进吗？**
A: 只能进入 `EXECUTION_REPORTED`。必须由另一份 acceptance work order 逐条看证据后才能 `PASSED`。

**Q: HTTP 502 后是否重开？**
A: 有 thread ID 或请求是否已发出不明确时恢复原 session；只有确认没有请求、没有 writer、没有 thread ID 时才允许一次重试。

**Q: 用户临时指定 Fast 或其他模型怎么办？**
A: 记录为本次或后续范围，按用户明确范围覆盖相应字段，其他字段继续使用默认值；不猜测 provider 映射。

## 生命周期

- **填补的 gap：** 给长任务提供“控制台只编排、执行者做实质工作”的会话级协议和可恢复证据。
- **什么会让它过时：** Codex 原生提供同等的会话角色隔离、可恢复工单和独立验收状态，并且能明确显示实际 provider/tier 时，可删除重复的手工层。
